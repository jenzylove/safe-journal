# Security

Safe Journal holds no keys and no plaintext on any server. Keys are derived in the browser from the passphrase and kept only in memory; entries are encrypted with AES-256-GCM before they leave the browser. The data format is in [arkiv/schema.md](arkiv/schema.md).

If you find a way to read, alter, delete or link someone's journal, or to drain the funding endpoint cheaply, please open a private security advisory on this repository instead of a public issue. All data in this repository and the demo is synthetic; never test with real personal information.

## Threat model

| Who | What they can do | What they cannot do | What Safe Journal does about it |
|---|---|---|---|
| Someone who checks the phone | Look at the screen, the browser history, the app list | Find entries on the device: nothing is stored there (no local storage, no cache, no cookies) | Private tab advice, a neutral "Notes" tab title, Leave now on every screen (or Escape three times), screens that add no history, the journal locks after two minutes in the background or fifteen minutes idle |
| Someone who forces the passphrase out of her | Read the journal | Delete or change any entry: each is owned by a burn address and readonly | A second, everyday passphrase that opens a separate journal of ordinary notes. Nothing on Arkiv links the two journals; funding them one after the other could, so she can fund one herself from the faucet |
| Anyone on the internet | See each journal address and, per address: how many entries, when each was written, its lifetime, whether it may be extended, whether a photo is attached, and the `app=safejournal` label. Find journal addresses through that label or through the funder's transfers. Watch an address live | Read any entry, photo, category or time she gave: all of it is encrypted, padded to a size bucket and bound to its entity key | Three public labels only; everything else is inside the ciphertext. The address itself is a random looking key derived from the passphrase and tied to nothing else |
| Someone guessing passphrases offline | Try passphrases against public ciphertext for as long as they like. The Argon2id salt is shared by every journal (there is no account to hold a per person salt), so one guess is tested against all journals at once | Get anywhere against six different random words from the 2048 word list (about 66 bits behind Argon2id with 64 MiB of memory) | New journals can only start from six different words the app generates. A phrase a person makes up can open an existing journal but never start a new one |
| Whoever holds a share link | Read the entries the link was made for, for as long as they exist, and copy them | Read any other entry: each entry has its own key, and a link carries only the chosen ones | The link is built in the browser and never sent to a server; the key leaves the address bar as soon as the page loads; the app tells her to delete the sent message and clear the clipboard |
| Us (the site and the funding endpoint) | See the address of a journal that asks for funding, and the connection address of that request (used for an in memory rate limit, never stored; the hosting platform keeps its own request logs) | See content, keys or passphrases. Delete, edit or hide entries | If the site disappears, the one file reader opens any journal straight from Arkiv. Anyone can fund a journal from the public faucet instead of our endpoint |
| The Arkiv node that answers reads | See which journal address a connection reads | Read content | The reader can be pointed at any other Arkiv node |

Out of scope: spyware already on the phone (it sees the passphrase as it is typed), a person forced to unlock the phone while the journal is open, and Arkiv itself failing. Expiry removes an entry from Arkiv's state but not from the chain's history, so privacy rests on the key, not on expiry. Tiramisu is a testnet: this build demonstrates the design; it is not yet a place for real evidence.
